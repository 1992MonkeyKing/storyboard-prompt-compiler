# 规格解读记录（阶段 1 实施时）

实施阶段 1 时发现的规格笔误与边界语义解读。凡是影响验收文本（T2）的，
以验收文本为准；其余均为可逆的默认实现，改一处函数即可。

## 1. 笔误修复（有验收文本为证，非自由发挥）

- `templates/seedream.json`：`assetLabel.image` 由 `"图{cn}"` 改为 `"图{cn}"`
  （SPEC.md 第 160 行少了右大括号；T2 要求输出"图一"，修复被验收标准唯一确定）。

## 2. 规范化补足（T2 逐字验收所必需）

- 规范化第 2 步在规格三种合并之外，补了 `"。，"→"。"`。
- 原因：Seedream 模板 `[{light}][，{color}][，{material}][，{styleText}]`
  在 light/color 为空时，`[，{material}]` 保留的前导"，"落在上一句"。"之后
  形成"。，"；验收文本要求此处为"平视。充电盒"，不用此规则推导不出验收文本。
- 实现：`normalize()` 内循环到稳定；同属"合并重复标点"一类。

## 3. 边界语义（默认实现，均不影响 T1–T5）

1. `dialogueText` 在 `{#each segments}` 循环内按**当前分段**计算：
   `segment`（从 1 开始）指向对应分段；未填进最后一段；超出范围进最后一段；
   同一段多条用"；"连接。——由"编译时放进对应分段"唯一确定。
2. 嵌套可选块：每个块只检查**本级**直接引用的字段；嵌套块各自独立判断。
   例：文字内容有、位置无 → `画面文字为"xxx"。`（内层省略，外层保留）。
3. `{#each assets}` 按镜头 `assetIds` 的顺序迭代；标签编号按类型、
   以 `project.assets` 上传顺序分别从 1 计数。
4. 模板未定义某素材类型的 `assetLabel` 时，标签兜底为 `{kind}{n}`
   （如 `video1`）；确定性，不抛错。
5. `{cn}` 中文数字：一～九十九、一百～九千九百九十九按常规读法生成。
6. 字段值清洗（规范化第 1 步）作用于所有字段含派生字段：去首尾空格、
   去末尾连续的"。"、"，"、"；"。
7. 行首标点删除集合：`，。、；：？！…·—`（不含引号/括号，避免误删正文）。
8. `compile()` 遇到未知镜头 id / 平台 id 抛错（确定性失败，不静默）。

## 4. 数据文件口径

- `vocab/zh.json` 结构：`{字段: {label, options, allowCustom}}`，
  `move` 下分 `type/amount/speed/direction` 四组；`direction` 含空字符串选项。
- `examples/xtech-tvc.json`：S01 逐字取自 SPEC.md 第二部分；
  S02（图像镜头）字段取自 SPEC.md 第四部分 §5 的图像样例。

## 5. 阶段 3 实现口径（2026-10-17）

1. 拆解提示词正文存于 `templates/breakdown-prompt.json`（从 SPEC.md 第六部分逐字提取），
   `{景别选项}` 等 6 个占位符由 `src/ui/breakdown.ts` 按 `vocab/zh.json` 填充；
   src/ 中不写任何提示词措辞。
2. 词表外取值只检查非空值；`allowCustom` 字段（构图/光线/音乐）永不标红；
   “最接近的合法选项”用字符级编辑距离最小者。
3. 档案卡 id 冲突：`保留现有` 丢弃导入卡（引用指向现有卡，不覆盖）；
   `重命名导入` 生成 `{id}_导入{n}` 并改写导入镜头中的引用；全部冲突解决后才可确认。
4. 导入镜头状态一律设为“草稿”；与现有镜头 id 冲突时自动改名（`{id}_导入{n}`）。
5. 导出 TXT/CSV：每镜按其类型匹配平台编译（video→Seedance 2.5，image→Seedream），
   CSV 含 BOM（Excel 直接打开不乱码），提示词字段按 CSV 规范加引号转义。
6. 参数行显示与复制共用 `paramDisplay()`；缺失值为“未设置”（界面文字，非提示词措辞）。
